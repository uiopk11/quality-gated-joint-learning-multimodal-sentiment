## 2. 按顺序补齐现有实验

先在 `problem2_solution/` 中激活原有可运行环境，查看已有记录：

```powershell
python -X utf8 run.py verify --checkpoints
python -X utf8 run.py report --all
```

**以下四条会实际执行评价；按顺序运行即可，不更新模型参数。** 执行前若报告已显示对应条件完成，就跳过该条，避免重复推断。

```powershell
# 1. MAE M0：补完整输入 test
python -X utf8 run.py evaluate --version four-models --run-name fm_mae_m0_s1111_r2 --split test

# 2. MAE M2：旧流程一次补 mixed test + valid/test 全部 paired（含 complete）
python -X utf8 run.py evaluate --version four-models --run-name fm_mae_m2_s1111 --split test

# 3. M3：补 valid 的配对缺失面板，同时保存 clean/mixed valid
python -X utf8 run.py evaluate --version four-models --run-name fm_v1_m3_s1111 --split valid --paired

# 4. M3：补 test 主结果及配对缺失面板
python -X utf8 run.py evaluate --version four-models --run-name fm_v1_m3_s1111 --split test --paired

# 5. 只整理上述已保存结果及图表，不再运行模型
python -X utf8 run.py report --all --organize
python -X utf8 run.py report --all
```

M1 已有 clean valid/test，无需为主表重跑。M0/M2 走恢复后的旧评价器：只接受 test，不能传 `--evaluation-output` 或要求另跑 valid；M0 不支持 paired。M2 的旧 test 流程总是同时运行两个划分的完整面板，不需要加 `--paired`。其中全量 `complete/complete` 会在报告中归入 clean，补齐 M2 的 clean valid/test。

M3 默认另建 `outputs/<run>/evaluations/<自动生成的评价ID>/`，结束后与父目录报告关联。也可用 `--evaluation-output <未占用的新目录>` 明确指定位置，但日常无需手动建立散落的 comparison 目录。已有独立评价不是新的训练 run。

官方明确要求 valid 基础评价；本项目同时保留 test 主表和规律复核作为固定流程，不能据 test 重新挑权重、调阈值或改超参数。恢复 M0/M2 不意味着今后任意设备的重跑必须恰好得到同一小数。

## 4. 缺失规律：固定权重，改变输入条件

M2/M3 用同一冻结 `mix_v1`、相同 ID、相同面板条件评价。下面共用 19 个唯一条件，**不是 19 次训练**。第 2 节命令会一并运行这些面板。

| 面板 | 控制设置与条件 | valid/test 共同 N | 需要回答的问题 |
|---|---|---:|---|
| `modality`，必做 | 40% 居中单段；T、A、V、TA、TV、AV、TAV | 721/726 | 哪些受损模态或组合影响更大？M3 相对 M2 是否改善？ |
| `rate`，必做 | TAV 同步居中，0/20/40/60/80% | 713/719 | 缺失加重时分类与强度指标怎样变化？ |
| `position`，必做 | TAV 40% 单段，head/center/tail | 708/717 | 相同缺失量的头/中/尾是否存在差异？ |
| `shape`，必做的时长/形态分析 | L≥20，TAV 各缺 8 位置，1×8、2×4、4×2、8×1 | 409/397 | 总量相同时，长连续缺口与短分散缺口有何差异？ |
| `synchrony`，已有流程附带补充 | TAV 各 40%，共同起点/各模态独立起点 | 724/727 | 跨模态缺口同步程度的影响如何？ |

T/A/V 指文本/音频/视觉局部受损；不是把整种模态删除。`complete` 全量 N=728/727；rate 的 0% 条件必须使用 rate 面板的共同子集 713/719，不能拿全量 clean 分数直接替代。各条件可适用样本数也不能代替该面板共同 N。

每个必做面板保存四指标表，至少绘制 Accuracy、Macro-F1、MAE 曲线或分组柱图，Pearson 同表给出；写明 M2/M3 的同条件差值、最明显退化及失败场景，不预设改进一定更优。统计人工目标率和最终实际率时要区分每模态 k/L 与三模态槽位率，使用冻结 metadata 的真实记录。

“时长”采用连续有效位置数和占比：附件二没有逐词时间戳，50 是最大存储长度，不能转换成秒。rate 同时改变比例和单段长度；shape 固定总量但同时改变连续段长与段数。这些实验支持长度/分散形态规律，不能宣称完全隔离物理时长单一因素。模态组合的总丢失量也不同，解释时不能忽略。

## 5. 主方法比较与消融分别汇总

| 表 | 使用记录 | 评价条件与作用 |
|---|---|---|
| 主方法比较 A | `fm_mae_m0_s1111_r2` 对 `fm_v1_m1_s1111` | 同 clean valid/test：旧回归适配整体方案对当前联合方案 |
| 主方法比较 B | `fm_mae_m2_s1111` 对 `fm_v1_m3_s1111` | 同 clean/mixed valid/test 与同 cohort paired：缺失场景整体方案 |
| 控制消融 A | `fm_v1_m0_s1111` 对 `fm_v1_m1_s1111` | 统一 Accuracy 协议，已有 clean valid/test；联合预测策略有/无 |
| 控制消融 B | `fm_v1_m2_s1111` 对 `fm_v1_m3_s1111` | 统一 Accuracy 协议，已有 clean/mixed valid；M3 补 test 后可扩展 test |

主表保留各自原生协议：MAE 基线与改进模型的损失、分类决策、选模和早停不同，结论是整体方案效果，不能把全部差异归给分类头。新 MAE 基线不能用旧 Accuracy 结果替换缺项。

两组控制消融已核对保存配置：除方法/类别决策、分类权重 0→1、回归权重 1→0.5 外，共同配置一致；数据、seed、选模和早停规则相同。这可以回答“引入整套分类与强度联合预测策略是否有效”，同时涉及分类头、损失配比和类别输出方式，**不是分类头、CE 或 DLFR 某个组件各自贡献的独立证明**。现有 valid 指标足以先完成这张消融表，无需再次训练四个模型。

自动 `outputs/comparisons/` 当前只处理上述 Accuracy 同协议对照。MAE 主比较需按此处指定记录另行汇总，软件尚未自动生成跨协议主表。汇总时保留权重 SHA256、样本 ID/cohort 与原指标来源，Accuracy/F1 越大越好、MAE 越小越好，不把不同条件混进同一差值。

官方没有指定必须拆高层一致性/低层重建，也没有要求关闭整个 DLFR。本轮不再把这些独立训练列为必做。论文若另行声称“某单独模块带来多少提升”，才需要与该主张匹配的额外控制实验。

## 6. 图表与错误归因：不新增训练

`report --all --organize` 从已有记录生成各训练目录的 `analysis/report.md`、`analysis/figures/` 和 `analysis/error_cases.csv`。图表文件存在不代表论文分析完成，按下表检查覆盖并补写结论：

| 产物 | 具体内容与读法 |
|---|---|
| 训练曲线 | train/valid 的原逐轮损失或指标，标明最佳/停止 epoch，解释过拟合或早停；缺历史不补画 |
| 分类图表 | valid clean/mixed 分开；混淆矩阵原计数及行归一化、各类 Precision/Recall/F1 与样本数，重点看中性与正负混淆 |
| 强度图表 | 真值-预测散点、残差分布，检查大误差、强度收缩和极值；保留原连续输出 |
| 缺失规律图 | 第 4 节必做四面板，图注带 split、N、条件、实际率/长度和固定权重 |
| 代表错误案例 | 负/中/正、极性与强度不一致、大误差各选有依据的案例；记录 ID、真值、预测、缺失模态/区间、同一样本 clean 与受损变化 |
| 文字归因 | 区分观测事实与推测：中性边界、样本不均衡、关键线索受损、原生零特征等；不能把猜测写成已证明原因 |

案例仅可用附件二实际提供的文本/特征及位置；没有原视频、语音波形或时间戳时不伪造回看片段。clean 与缺失配对观察用相同 ID，并记录失败/成功两种变化，避免只展示有利案例。

已有[历史可信度审计](../reproducibility/records/multitask_leakage_audit_20260925/results_audit.json)及[输入干预记录](../reproducibility/records/multitask_leakage_audit_20260925/prediction_probe.json)仍保留，范围是旧多任务 `mt_m0` 对旧标准化回归，不能当成所有新模型已审计。该比较负类改善但中性 F1 下降，单种子证据不足以声称稳定、显著或所有类别都提升。

## 7. 论文中要交代的模型与训练协议

共同输入采用附件二 aligned 版本：train/valid/test 为 3395/728/727；负/中/正分别为 967/758/1670、206/184/338、207/158/362。文本用 `text_bert[3,50]`，A/V 为 50×74、50×35。保留原样本、划分、内部缺口及原生全零，不合并 valid/test 训练；标准化只在原 train 的有效且非整行全零 A/V 行拟合，详见数据协议。

共享主干是可微调 BERT、A/V LSTM（hidden 16/32）、128 维投影、2 层 4 头 EMT 和融合回归头。M1/M3 在融合 ReLU 表征上增加 `Linear(128,3)`（387 参数）。回归头独立输出强度，不按分类改符号、不强制中性归零。

| 模型 | 输入与目标函数 | 最佳权重与分类决策 | patience / eval batch / min_delta |
|---|---|---|---|
| M0 | clean，L1 回归 | clean valid MAE 最小；随后校准固定阈值 | 8 / 8 / 1e-6 |
| M1 | clean，CE + 0.5 L1 | clean valid Accuracy→Macro-F1→MAE→最早 epoch；logits argmax | 8 / 16 / 1e-12 |
| M2 | clean+固定 mixed 双视图 L1，加完整 DLFR | mixed valid MAE 最小；随后校准固定阈值 | 5 / 8 / 1e-6 |
| M3 | 双视图各 CE + 0.5 L1，加完整 DLFR | clean/mixed valid 指标等权均值，排序同 M1；logits argmax | 8 / 16 / 1e-12 |

M0/M2 阈值网格为 0,0.05,…,1.00，按 valid Macro-F1、Accuracy、较小阈值依次确定，之后对 test/各面板冻结。目前新 M0/M2 阈值分别为 0.35/0.20。真值按负/零/正三类；旧 Accuracy 对照采用自己的选模和阈值协议，不能改写成上述 MAE 流程。

DLFR 保留四组对称负余弦高层一致性与三模态 SmoothL1 低层重建；目标表示 detach，低层监督只用正文中原可观测且被人工遮蔽的位置，A/V 目标在标准化单位。两项外层权重各 1；推理只读取当前输入，不使用完整参考，不执行辅助恢复头替换输入。

当前共有 seed=1111、最大 20 epoch、训练 batch=16、累积=4，Adam，BERT 学习率 2e-5、其余 1e-4，无调度器；精确参数、优化器细节与实际轮次引用各 run 的 `config.json`、`training.json`、原 history。基础 BERT 与新 EMT 初始化不从已训练情感模型热启动。

EMT-DLFR 固定提交 `e4216215565292360e9c3fc43c8cd6e127df19c2`，来源见[源码清单](../reproducibility/source_provenance.json)；BERT 为 `google-bert/bert-base-uncased`，revision `86b5e0934494bd15c9632b12f734a8a67f723594`，见[模型来源](../resources/pretrained/bert-base-uncased/source_manifest.json)。论文称“EMT-DLFR 本题适配回归基线”，不能写成完全复现原论文数据与实验。微调后的 BERT 是训练权重的一部分，不能换回基础 BERT 冒充相同模型。

目前不需要重训。以后仅在明确新增 seed/重复实验时使用未占用的新 run 名称，例如下面是新运行模板，**不是本轮待执行清单**：

```powershell
python -X utf8 run.py train --version four-models --method M0 --run-name fm_mae_m0_new
python -X utf8 run.py train --version four-models --method M1 --run-name fm_v1_m1_new
python -X utf8 run.py train --version four-models --method M2 --run-name fm_mae_m2_new
python -X utf8 run.py train --version four-models --method M3 --run-name fm_v1_m3_new
```

只改名字不会改 seed，精确配置以对应 `--help` 为准。新 M0/M2 不接收 `configs/four_models_v1.json`；M1/M3 保持现有配置与模型。绝不删除已有 run 来复用名称。

## 8. 附件三与最后交付

历史清单记录附件三 aligned 版应有30个输入 PKL，但当前包的 `resources/data/` 为空，只有 `reproducibility/attachment3_file_inventory.csv` 和审计记录。拟以冻结后的 M3 作为专项模型；训练、调参和阈值仅用附件二 train/valid，附件三无标签，只用于最终推断。当前 `run.py predict` 的无标签适配也尚未核实完成，**不要直接执行它并期待生成提交结果**。

这一项剩余工作按顺序是：

1. 从正式数据目录或队友工作区补回附件三输入，逐文件核对现有清单中的文件名、大小和SHA-256；同时确认附件二输入可供预处理与复核使用。
