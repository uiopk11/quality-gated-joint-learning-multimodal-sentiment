# 复现指南

## 先选择复现层级

1. **阅读与结构核验**：运行`python -X utf8 scripts/verify_repository.py`，查看已有CSV/JSON/SVG及说明。完整版论文暂不上传。只需Python标准库；读取特征还需要NumPy。
2. **复现冻结模型推断**：准备官方附件3/4、M3/M1权重和公开BERT，在各模块指定环境中运行原入口。
3. **重新训练与评价**：还需附件2对齐PKL、固定缺失掩码和训练依赖；使用新的run名字。不同软件栈不保证浮点结果逐位相同。
4. **重新提取视频特征与证据时间轴**：还需原视频和问题1的完整外部工具链。

## 外部资源

模型权重取得方式及SHA256见根目录`外部权重下载说明.md`。M3放于`问题2/outputs/fm_v1_m3_s854/best.pt`；M1放于`问题3/q3_handoff/checkpoint/best.pt`。BERT初始化权重在问题2/3分别放置，配置和词表已随仓库提供。

官方数据不入Git。附件2对齐版放于`问题2/resources/data/attachment2/aligned_50.pkl`，附件3对齐30个PKL放于`问题2/resources/data/attachment3/aligned/`。问题3通过`E_TOPIC_DATA_ROOT`读取官方`E题数据`根目录。不要用未对齐版替换对齐版。

## 问题1

进入`问题1/`执行`python 读取提交特征.py`读取统一特征。需要重新处理附件1时，按`environment/README.md`建立Python、MFA、OpenFace、FFmpeg和模型资源，并在`code/config.yaml`中填写`<PROJECT_ROOT>`路径，设置新输出目录。

从`问题1/code/`运行质量审计、阈值检查、特征生成和输出审计，具体顺序见本模块README。该配置依赖原资源布局，可把资源目录与仓库代码目录分开放置。MFA/Kaldi工作目录在Windows下需采用纯英文路径。

## 问题2

进入`问题2/`。依赖安装、预测完整命令、`--check-only`、训练/评价选模协议均以本模块README为准。本整理保留原配置、源哈希和固定掩码；如报来源错误，应恢复对应原件，不能删除登记或关闭校验。

新增的`docs/`及补回的小型资源改善了包布局，但`run.py verify --checkpoints`仍需要官方附件2/3、公开BERT以及实际checkpoint全部就位。仅仓库下载完成时不应期待此命令成功。

## 问题3

进入`问题3/`，按`environment-q3.yml`创建独立环境，指定该环境解释器。设置官方数据根，准备M1和BERT，然后依次运行：

```powershell
python -B src/audit_attachment4.py
python -B src/run_attachment4.py --device cuda
python -B src/run_fidelity_validation.py --device cuda --random-repeats 10
python -B src/export_tables.py
python -B src/audit_results.py
```

原脚本会写`results/`。已有结果属于冻结快照；如需保留原输出，应在单独克隆/工作副本中复现。CPU可用时将设备改为`cpu`，运行更慢。

可靠时间回溯额外设置`Q1_RESOURCE_ROOT`为问题1外部资源根，使用该环境解释器运行`run_qg_hta_attachment4.py`、`merge_qg_hta_evidence.py`、`audit_qg_hta.py`，然后生成解释卡和正式提交CSV，顺序见模块README。

验证集诊断代码`analyze_validation.py`读取随包M1逐样本表；无需重新训练，但需要绘图依赖。`supplementary/plotting/`是原论文展示代码，仍含原开发路径假设；运行前需要检查路径，不能认为全部展示脚本已经跨平台适配。
